## Запуск локально

Из корня `RevshareBD/`:

```bash
# Web (HTTP)
revshare-web        # точка входа: revshare.web:run
                    # слушает на 127.0.0.1:43127

# Worker (фон/планировщик, отдельно)
revshare-worker     # revshare.worker:run
```

**БД и секреты уже сконфигурированы.** Не задавай `REVSHARE_DB=...` и не редактируй `REVSHARE_ADMIN_PASSWORD` руками:
- БД по умолчанию: `data/revshare.db` — там реальные данные партнёров, не тестовая копия.
- Секреты: `data/secrets.env` (токен Telegram-бота, доступы к Google Sheets, SMTP, MySQL Altegio).

## После правки любого `.py` — рестарт ОБОИХ сервисов

Python не перечитывает `.py` файлы. Долгоживущих процессов **два**:

| Сервис | Что это | Как проверить |
|---|---|---|
| `revshare-web` | uvicorn на :43127 | `ps aux \| grep revshare-web \| grep -v grep` |
| `revshare-worker` | планировщик + telegram polling | `ps aux \| grep revshare-worker \| grep -v grep` |

Если правил код бота или воркера — перезапусти оба. Если правил только web — перезапусти web (но всё равно проверь, что воркер жив).

## Что НЕЛЬЗЯ трогать без явной просьбы

- `data/revshare.db` — прод-БД с историей партнёров.
- `data/secrets.env` — реальные токены, доступы, пароли.
- `data/uploads/` — загруженные партнёрами файлы (регуляторика, источник для сверки).
- `RevshareBD/data/` в целом — рабочая среда, не трогать.
- `.env`, `.env.*` — локальные настройки, не трогать.

**Не пересоздавай окружение** (не удаляй и не инициализируй БД заново) «чтобы починить». Если что-то не работает — сначала разберись почему.
