# Integration Hub revshare

Система сбора ежемесячных отчётов партнёров Хаба Интеграций. Партнёр заполняет персональную форму, система сохраняет оборот и Location ID, сопоставляет их с данными Altegio и готовит результат для [Partnerships Altegio Revenue Accrual](https://docs.google.com/spreadsheets/d/1GoEn9TiJHMI_7YQ9LkzBnLAoKRB_PvtnootyjQAta5A/edit?gid=671431539).

## Что уже работает

1. Реестр партнёров с персональными ссылками.
2. Форма партнёра: один месячный файл с оборотом, валютой, revshare и Location ID. Если у партнёра несколько приложений, в файле используется одна строка на приложение и салон: `Application`, `Location ID`, `Turnover`, `Currency`. Старые отчёты без колонки приложения остаются совместимыми.
3. Контрольный снимок подключённых и активных клиентов Altegio. Его можно вставить вручную или загрузить JSON / выгрузку по `ALTEGIO_SNAPSHOT_URL`. В JSON можно передать блок `locations` с названием филиала, датой подключения, последней активностью API и признаком сумм по API. Эти поля попадают в CSV расхождений. На той же странице ниже список кандидатов на отключение.
4. Автоматическая сверка отсутствующих, неизвестных и повторяющихся Location ID. Приложение в каждой строке сопоставляется с точной карточкой APP по ссылке, ID или названию; несопоставленные строки выделяются отдельно.
5. Сводка за месяц со статусами, суммой revshare и оценкой риска. Фильтры стоят в шапке таблицы по каждой колонке, заголовки сортируют по возрастанию и убыванию, внизу строка «Всего». CSV скачивается с учётом фильтров и сортировки.
6. Если отчёт не в долларах, рядом показывается сумма в долларах для внутренней работы. Для каждого отчётного месяца берётся средний дневной курс. Первого числа курс закрытого месяца подставляется сам, в Настройках месяц можно поправить вручную. Это справочный пересчёт, выплата идёт в валюте партнёра.
7. У каждой ссылки на приложение хранится точная категория из Хаба Интеграций. Используется справочник Altegio: ИИ-боты и ассистенты, Чат-боты, СМС агрегаторы, Онлайн-запись, CRM, Аналитика и остальные категории. Страница называется «Информация о партнёре» и разделена на вкладки: основная информация, настройки, история сданных месяцев с графиком revshare и подключений.
8. Разбор Excel, CSV, PDF и текстовых сообщений через CLI, а также чтение реестра Location ID прямо из приложенного файла.
9. Интерфейс админки на английском и русском. На форме партнёра доступны английский, украинский, польский, венгерский, португальский (бразильский) и русский. Форма открывается на языке карточки, партнёр может переключить язык сам.
10. Название и страна юридического лица, несколько ссылок на приложения, которые входят в расчёт партнёра.
11. Если активного Location ID нет в файле, партнёр видит понятный порядок действий, может скачать расхождения в CSV, загрузить исправленный отчёт или указать причину. Подключённые, но неактивные не блокируют отправку.
12. Установки без активности API не блокируют отправку. Вместо списка из сотни ID партнёр отвечает на один вопрос, платит ли кто-то из них, и может скачать список. Ответ «никто не платит» сохраняется как заявление по каждому филиалу, в отчёте видно счётчик и противоречия по платёжным колбэкам. Такие установки становятся кандидатами на отключение, отключает их клиент или партнёр, а не Altegio в момент сдачи отчёта.
13. Внутренняя сверка причин с активностью API и платёжными колбэками.
14. Общие параметры собраны в Настройках: публичный адрес формы, отправка в Telegram, даты уведомлений для всех партнёров, тексты по языкам и курсы к доллару. В карточке партнёра можно оставить общие даты или задать свои. Суббота и воскресенье переносятся на понедельник.
15. Отправка на почту через SMTP. Настройки берутся из `data/secrets.env`: `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`, `SMTP_FROM_NAME`, `SMTP_REPLY_TO`, `SMTP_MODE`. Письмо уходит в фирменном оформлении: заголовок Хаба Интеграций, текст уведомления, кнопка со ссылкой на форму, срок сдачи, список того, что подготовить. Рядом идёт текстовая версия для клиентов без HTML. В карточке есть ссылка «Посмотреть письмо».
16. Telegram бот отправляет ссылку на отчёт. Партнёр один раз открывает персональную ссылку бота. Внутренняя сводка привязывается через `/start digest`, если Telegram user id указан в `REVSHARE_ADMIN_TELEGRAM_USER_IDS`. Иначе чат задаётся в Настройках. Плановые уведомления уходят сами каждый час, повторно одно и то же сообщение не шлётся.
17. На странице Начисления два списка. «Готовы к отправке»: подтверждённые отчёты с галочками, можно выбрать несколько партнёров и подтвердить отправку одной кнопкой. «Очередь записи»: уже подтверждённая отправка с оборотом и суммой revshare. На странице отчёта есть только подтверждение отчёта. После подключения Google Sheets оборот записывается в [Partnerships Altegio Revenue Accrual](https://docs.google.com/spreadsheets/d/1GoEn9TiJHMI_7YQ9LkzBnLAoKRB_PvtnootyjQAta5A/edit?gid=671431539) автоматически. Формулы Share и Paid не перезаписываются.
18. Административные страницы закрываются паролем `REVSHARE_ADMIN_PASSWORD`. Форма партнёра остаётся по персональной ссылке.

Красный статус означает существенное расхождение, а не доказанный обман. Проверка смотрит Location ID, revshare против ставки договора, резкие скачки оборота и пересечение клиентов между партнёрами. Полный поток из Altegio API подключается, когда появятся доступы.

## Google Sheets

Таблица уже указана в `partners.yaml`. Для записи оборота нужен service account Google Cloud:

1. Создайте service account и скачайте JSON ключ.
2. Откройте таблицу и дайте `client_email` из JSON права редактора.
3. Скопируйте `secrets.env.example` в `data/secrets.env` и добавьте одну из переменных:
   * `GOOGLE_SERVICE_ACCOUNT_FILE=/полный/путь/к/ключу.json`
   * `GOOGLE_SERVICE_ACCOUNT_JSON={"type":"service_account",...}` (одной строкой)
4. При необходимости переопределите id: `REVSHARE_GOOGLE_SHEET_ID=1GoEn9TiJHMI_7YQ9LkzBnLAoKRB_PvtnootyjQAta5A`

Проверка доступа и поиск колонки месяца:

```bash
python -m revshare sheet-probe --month 2026-08
```

Ручная отправка очереди:

```bash
python -m revshare sheet-flush
```

В интерфейсе запись идёт при открытии страницы Начисления и сразу после подтверждения отправки. В очереди видны статусы «В очереди», «Записано», «Ошибка» и адрес ячейки.

## Запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
pytest
revshare-web
```

В production фоновые задачи запускаются отдельным процессом:

```bash
revshare-worker
```

Для веб-процесса в production задайте `REVSHARE_WEB_BACKGROUND_TASKS=0`, чтобы Telegram polling и планировщик не запускались в нескольких web workers.

Откройте `http://127.0.0.1:43127`.

Для проверки создан демонстрационный партнёр. Его форма:

```text
http://127.0.0.1:43127/submit/demo-partner
```

Данные хранятся в `data/revshare.db`, вложения в `data/uploads`. Папка исключена из git.

## Логика проверки

Партнёр прикладывает файл, и система сама вычитывает из него Location ID. Сначала ищется колонка реестра по заголовку: Location, Salon, Branch, филиал, салон, точка, заклад. Если колонки нет, файл сканируется на числовые ID, суммы и проценты при этом пропускаются. Поле Location ID в форме остаётся резервным: для тех, кто присылает только короткий список без файла.

Система рассчитывает риск по отсутствующему реестру клиентов, дубликатам, активным Location ID, которых нет в отчёте, и неизвестным Location ID. Обязательный комментарий запрашивается только по активным в течение месяца Location ID, которых нет в файле. Подключённые на конец месяца, но без активности API, показываются отдельно и не блокируют отправку. Причины видны в админке вместе с независимой проверкой по активности API и наличию платёжного колбэка.

Для нескольких приложений проверка выполняется отдельно по каждому APP: система сравнивает Location ID в соответствующем блоке с отдельным снимком подключений и активности этого приложения. В интерфейсе видны активные салоны Altegio, салоны, пропущенные партнёром, и ID, которые партнёр указал, но которые не подключены к этому APP. Если отдельного снимка пока нет, блок помечается как «проверка недоступна», а не как подтверждённый совпадающий результат.

Эта сверка показывает подозрительные расхождения и не доказывает сама по себе, что партнёр занизил оборот. Для проверки именно суммы нужны независимый API партнёра, биллинг или read-only источник с платежами; сейчас система проверяет структуру отчёта, принадлежность салонов приложениям и доступные факты Altegio.

Контрольный снимок сейчас вводится в разделе «Данные Altegio»: подключения на конец месяца, активность API и Location ID с платёжным колбэком. Отсутствие колбэка само по себе не доказывает отсутствие оплаты. Поэтому такая причина получает статус «Нужна проверка», а найденный колбэк даёт статус «Противоречит данным». Обновление снимка автоматически пересчитывает проверку уже отправленных объяснений. Обещание включить клиента в следующем месяце автоматически подтверждается или опровергается при получении следующего отчёта. Позже ручной снимок заменит регулярная синхронизация из внутренних источников.

## CLI для входящих файлов

```bash
python -m revshare status --month 2026-08
python -m revshare ingest inbox/2026-08 --month 2026-08
python -m revshare preview --month 2026-08
python -m revshare import-usage --month 2026-08 --file data/altegio/2026-08.json
```

CLI готовит `drafts/YYYY-MM.json`. Команды `sheet-probe` и `sheet-flush` работают с живой таблицей, когда настроены credentials.

## Структура

* `src/revshare/web.py`: веб приложение
* `src/revshare/store.py`: база и проверки
* `templates/`, `static/`: интерфейс
* `partners.yaml`: карта для текущего Google Sheet
* `src/revshare/extract.py`: разбор файлов
