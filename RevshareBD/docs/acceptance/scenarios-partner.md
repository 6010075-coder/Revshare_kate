# Сценарии приёмочной проверки — Партнёр

Пошаговые сценарии для каждой партнёрской истории. Источник историй: [`user-stories.md`](./user-stories.md) (P-01..P-17). Протокол прогона заполняется по [`run-template.md`](./run-template.md).

## Как читать

Каждый сценарий — это «предусловия → шаги → ожидаемый результат». Поле **Тип** говорит, как сценарий проверять:

- **авто** — уже закрыт pytest-тестом, при изменении смежной логики нужно запускать его.
- **ручной** — проверяется в живом окружении (бот / веб / админка).
- **гибрид** — есть и авто-часть (внутренняя логика), и ручная часть (визуальная сводка или взаимодействие с Telegram).

## Предусловия, общие для всех сценариев

- Подняты оба сервиса: `revshare-web` (uvicorn :43127) и `revshare-worker` (планировщик + telegram polling).
- В БД есть хотя бы один партнёр с привязанным приложением, ставкой и валютой.
- Секреты в `data/secrets.env` валидны (Telegram, при необходимости SMTP/Sheets).
- Тестовый файл-шаблон — `report_template.py:build_report_template`.

## P-01. Получить шаблон

**Предусловия:** партнёр запустил бота (`/start TOKEN` или просто `/start` после привязки).
**Тип:** ручной + авто (`tests/test_bot_keyboard.py`).

**Шаги:**
1. Открыть Telegram-бота.
2. Нажать кнопку «Запросить шаблон» или отправить `/template`.
3. Получить файл, открыть его в Excel/LibreOffice.

**Ожидаемый результат:**
- Приходит Excel-файл с универсальным именем (без конкретного периода в имени).
- В стандартном приглашении нет периода и срока сдачи.
- Файл пригоден для заполнения: есть шапка, строки для клиентов, ячейка периода (B3).

**Автотесты:** `tests/test_bot_keyboard.py::test_send_template_on_button_press`, `::test_send_template_on_slash_command`.
**Код:** `src/revshare/bot.py` — обработчик кнопки и команды `/template`.
**Открытый вопрос:** Q-03 (см. user-stories.md).

## P-02. Загрузить отчёт

**Предусловия:** у партнёра есть заполненный шаблон, бот привязан.
**Тип:** авто (`tests/test_extract.py`, `test_bot_handlers.py`, `test_bot_strict_validation.py`).

**Шаги:**
1. Заполнить первый лист: 2–3 клиента с суммами, валютой, Location ID.
2. Добавить клиента после пустой строки.
3. Добавить клиента за пределами подготовленных строк.
4. На второй лист положить произвольный пример с другими данными.
5. Отправить файл боту.

**Ожидаемый результат:**
- Распознаны все клиенты с первого листа, включая «после пустой строки» и «за пределами подготовленных».
- Второй лист не попал в результат.
- Валюта взята из файла, при отсутствии — из карточки партнёра.
- Создан черновик, видна сводка.

**Автотесты:** `tests/test_extract.py::test_parse_partner_report_groups_rows_by_application`, `::test_parser_accepts_blank_template_without_leaking_examples`, `::test_parser_extracts_ten_column_template_with_line_items`. `tests/test_bot_strict_validation.py::test_accept_single_client_report`.
**Код:** `src/revshare/extract.py`, `src/revshare/bot.py::handle_partner_document`.

## P-03. Определить период

**Предусловия:** бот привязан, есть заполненный шаблон.
**Тип:** авто (`tests/test_phase2_acceptance.py`) + ручной (визуальная сводка).

**Шаги:**
1. В ячейке B3 первого листа указать месяц, **отличный** от подписи к сообщению в Telegram (например, файл за «март 2026», подпись «Отчёт за февраль»).
2. Отправить файл боту.
3. Повторить с русским названием месяца («Март 2026»), английским («March 2026»), числовым форматом («03.2026»).
4. Аналогично проверить через веб-форму `/submit/{token}`.

**Ожидаемый результат:**
- Период в черновике равен **значению в B3 файла**, не подписи.
- Все три формата месяца распознаются.

**Автотесты:** `tests/test_phase2_acceptance.py::test_fr02_period_russian_from_b3` и аналогичные `test_fr02_*`.
**Код:** `src/revshare/extract.py` — разбор B3.

## P-04. Исправить период

**Предусловия:** бот привязан, есть заполненный шаблон.
**Тип:** авто + ручной.

**Шаги:**
1. Очистить ячейку B3.
2. Отправить файл боту.
3. Повторить с B3 = «Месяц 13», «Q1», «abc» (нераспознаваемые значения).

**Ожидаемый результат:**
- Бот отвечает сообщением «исправьте файл и пришлите заново».
- Новый черновик в БД **не создан**.
- Повторная отправка с правильным B3 создаёт черновик.

**Код:** `src/revshare/bot.py::handle_partner_document` — ветка «период не распознан».

## P-05. Понять ошибку файла

**Предусловия:** бот привязан.
**Тип:** авто (`tests/test_bot_handlers.py`, `test_bot_strict_validation.py`).

**Шаги (три файла):**
1. **Повреждённый файл:** переименовать `.xlsx` в `.txt`, отправить. Другой вариант — отправить `.xlsx` с битым архивом.
2. **Без нужной таблицы:** отправить `.xlsx` с одним листом, на котором нет шапки с Location ID / оборотом.
3. **Некорректная сумма:** оставить ячейку оборота пустой или написать «abc».

**Ожидаемый результат:**
- Бот сообщает тип ошибки понятным языком.
- Для ошибки суммы — указывает конкретные номера строк.
- Никакой «отправленный отчёт» не создан (черновика тоже нет).

**Автотесты:** `tests/test_bot_handlers.py::test_handle_partner_document_bad_extension`, `tests/test_bot_strict_validation.py::test_reject_turnover_not_found`, `::test_reject_locations_missing`.
**Код:** `src/revshare/bot.py::handle_partner_document` — пост-парс валидация.

## P-06. Указать нулевую оплату

**Предусловия:** бот привязан.
**Тип:** авто (`test_bot_strict_validation.py`).

**Шаги:**
1. **Файл 1:** в строке клиента в поле оборота поставить `0`, остальное заполнить корректно.
2. **Файл 2:** оставить ячейку оборота клиента пустой.

**Ожидаемый результат:**
- Файл 1: черновик создан, бот предлагает подтвердить.
- Файл 2: бот сообщает об ошибке суммы с номером строки.

**Автотесты:** `tests/test_bot_strict_validation.py` — парные кейсы «ноль принимается, пусто отвергается».
**Код:** `src/revshare/extract.py` — разбор суммы; `src/revshare/bot.py` — проверка после разбора.

## P-07. Сдать отчёт с одним клиентом

**Предусловия:** бот привязан.
**Тип:** авто.

**Шаги:**
1. Заполнить шаблон с **одним** клиентом и одним Location ID.
2. Отправить боту.

**Ожидаемый результат:**
- Чек «отчёт отклонён, потому что один клиент» **не срабатывает**.
- Бот предлагает подтвердить отчёт.

**Автотесты:** `tests/test_bot_strict_validation.py::test_accept_single_client_report`.
**Код:** `src/revshare/bot.py` — отсутствие старой проверки на «мало клиентов».

## P-08. Сообщить об отсутствии клиентов

**Предусловия:** бот привязан.
**Тип:** ручной + авто (только парсер).

**Шаги:**
1. Открыть чистый шаблон.
2. **Не заполнять** ни одной строки клиента.
3. Отправить боту.

**Ожидаемый результат (после согласования Q-01):**
- Разборщик читает файл и видит «пустой отчёт».
- Поведение Telegram зависит от решения Q-01. Зафиксировать фактический результат в протоколе.
- Не считать сценарий пройденным, пока Q-01 не закрыт.

**Автотесты:** `tests/test_extract.py` — кейсы на пустой шаблон.
**Код:** `src/revshare/extract.py`, `src/revshare/bot.py` — пост-парс проверка.
**Открытый вопрос:** Q-01.

## P-09. Привязать единственное приложение

**Предусловия:** у партнёра ровно одно привязанное приложение, бот и/или веб-форма.
**Тип:** ручной.

**Шаги:**
1. Через Telegram: отправить файл, дождаться сводки.
2. Через веб-форму `/submit/{token}`: загрузить файл, дождаться экрана сверки.

**Ожидаемый результат:**
- В обоих случаях выбор приложения **не запрашивается**.
- Черновик привязан к единственному приложению партнёра.

**Код:** `src/revshare/store.py` — `assess` / логика автопривязки; `templates/submit.html`, `templates/submitted.html`.

## P-10. Выбрать приложение

**Предусловия:** у партнёра **несколько** привязанных приложений.
**Тип:** ручной.

**Шаги:**
1. Через Telegram: загрузить файл, в появившемся списке выбрать приложение A, подтвердить.
2. Через веб-форму: загрузить файл, выбрать приложение B, подтвердить.

**Ожидаемый результат:**
- Перед подтверждением виден список только своих приложений.
- После подтверждения отчёт привязан к выбранному.
- В админке `/reports/{id}` видно правильное приложение.

**Код:** `src/revshare/bot.py` — клавиатура выбора; `templates/submit.html` — селект.

## P-11. Узнать об отсутствии приложения

**Предусловия:** тестовый партнёр **без** привязанных приложений.
**Тип:** ручной + авто.

**Шаги:**
1. Через Telegram: отправить заполненный файл.
2. Через веб-форму: загрузить тот же файл.

**Ожидаемый результат:**
- Загрузка блокируется.
- Бот / страница возвращают понятное сообщение «обратитесь к администратору».
- Ни черновик, ни отчёт не созданы.

**Код:** `src/revshare/bot.py` — ранний отказ; `templates/submit.html` — проверка перед разбором.

## P-12. Не выбрать чужое приложение

**Предусловия:** партнёр A, партнёр B; у каждого свои приложения.
**Тип:** авто (через прямой запрос) + ручной (визуально).

**Шаги:**
1. Открыть страницу подтверждения партнёра A.
2. Убедиться, что в списке только приложения A.
3. (Техническая проверка) Передать в API идентификатор приложения B.

**Ожидаемый результат:**
- В UI список содержит только приложения A.
- Прямая попытка передать чужой `application_id` отклоняется (HTTP 4xx или «выбор отклонён»).

**Код:** `src/revshare/store.py` — `assess` (проверка владельца), `src/revshare/web.py` — обработчик подтверждения.

## P-13. Проверить данные перед подтверждением

**Предусловия:** бот привязан, есть заполненный файл.
**Тип:** ручной.

**Шаги:**
1. Загрузить файл с известными значениями (запомнить: число клиентов, оборот, валюту, приложение, период).
2. Сверить каждое поле в сводке бота.

**Ожидаемый результат:**
- В сводке указаны: партнёр, период, приложение, число клиентов, оборот, сумма к выплате.
- До подтверждения это **черновик**, не «текущий» отчёт.

**Код:** `src/revshare/bot.py` — форматирование сводки; `src/revshare/store.py` — статусы черновика/отчёта.

## P-14. Переприслать файл

**Предусловия:** у партнёра уже есть подтверждённый отчёт за период X.
**Тип:** ручной.

**Шаги:**
1. Сохранить подтверждённый отчёт (запомнить: оборот, версия).
2. Загрузить новый файл за тот же период, выбрать «отправить заново» (без подтверждения).

**Ожидаемый результат:**
- Появляется новый черновик.
- Ранее подтверждённый отчёт остаётся актуальным («текущим»), пока новый черновик не подтверждён.

**Код:** `src/revshare/store.py` — состояния `draft` / `current`; `src/revshare/bot.py` — кнопка «Отправить заново».

## P-15. Отправить исправленную версию

**Предусловия:** есть подтверждённый отчёт за период X, приложение Y.
**Тип:** ручной.

**Шаги:**
1. В админке подтвердить исходный отчёт.
2. В Telegram отправить исправленный файл за тот же период и приложение.
3. Подтвердить новую версию.

**Ожидаемый результат:**
- Создана **новая версия** того же отчёта.
- Прежнее подтверждение сброшено — админ должен подтвердить заново.
- История версий показывает обе.

**Код:** `src/revshare/store.py` — версионирование; `src/revshare/web.py` — `confirm_report` (сбрасывает).

## P-16. Не создать дубликат

**Предусловия:** на экране подтверждения черновика в Telegram.
**Тип:** ручной.

**Шаги:**
1. Открыть экран подтверждения.
2. Дважды быстро нажать «Подтвердить» (в пределах ~1 секунды).

**Ожидаемый результат:**
- Создан **один** отчёт и **одна** версия, не две.
- В админке нет дубля.

**Код:** `src/revshare/bot.py` — обработчик callback (идемпотентность), `src/revshare/web.py` — `confirm_report`.

## P-17. Сдать отчёты по нескольким приложениям

**Предусловия:** у партнёра ≥ 2 приложения, период один и тот же.
**Тип:** ручной.

**Шаги:**
1. За один месяц сдать отчёт для приложения A с суммой X.
2. Сдать отчёт для приложения B с суммой Y.
3. Подтвердить оба.

**Ожидаемый результат:**
- Оба отчёта присутствуют в `/admin/partners` и в `/reports/...`.
- Данные не перезаписаны: у каждого своя сумма и валюта.
- Ключ уникальности — `(partner_id, period, application_id)`.

**Код:** `src/revshare/store.py` — уникальный индекс; `templates/dashboard.html`, `templates/partner_edit.html`.
