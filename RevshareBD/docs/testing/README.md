# Тестирование Integration Hub Revshare

Раздел о том, как мы проверяем, что система работает.

## Что здесь

В проекте есть **два слоя проверки**, и они дополняют друг друга:

| Слой | Что это | Где лежит | Кто запускает |
|---|---|---|---|
| **Автоматизированные тесты** | pytest-юниты и интеграционные | `tests/` в коде | CI и разработчик |
| **Ручные приёмочные сценарии** | пошаговые проверки флоу, которые мы прогоняли руками | `testing/manual/` | админ / продакт перед релизом |

Автотесты — это «быстро и в фоне». Ручные — это «живой партнёрский путь, не описанный в коде».

## Структура раздела

```
docs/testing/
├── README.md                  # этот файл — навигация и зачем два слоя
├── automated/
│   └── README.md              # карта автотестов: что какой файл покрывает
└── manual/
    ├── README.md              # шаблон ручного сценария + как заводить новый
    └── <flow-name>.md         # конкретные сценарии (bot-flow, submit-flow, …)
```

## Когда что использовать

- **Поправил код** → запусти `pytest` (см. карту в `automated/README.md`, какой файл относится к твоей зоне).
- **Поменял флоу партнёра** (новая страница, новый шаг в боте, новое поле в форме) → обнови соответствующий ручной сценарий в `manual/`.
- **Готовишь релиз** → пройди 2–3 ключевых ручных сценария, прежде чем выкатывать (каких — список в `manual/README.md`).
- **Что-то непонятно в работе системы** → сначала ручной сценарий «как должно быть», потом смотри код.

## Конвенции раздела

- Пишем по-русски, без жаргона.
- Сценарий — это «что я делаю + что вижу». Не описание кода.
- Если сценарий ссылается на код — указываем файл и строку.
- Файлы называем по флоу, не по фиче: `bot-flow.md`, `submit-flow.md`, `reconciliation-flow.md`, а не `feature_29.md`.
