# Ручной сценарий: бот-флоу

Пошаговая инструкция «как руками проверить всё, что связано с Telegram-ботом». Один прогон занимает ~15 минут. За раз проверяет сразу несколько user stories: P-01, P-02, P-03, P-04, P-05, P-06, P-07, P-09, P-10, P-11, P-13, P-14, P-15, P-16, P-17.

## Предусловия

- Оба сервиса запущены: `revshare-web` (uvicorn :43127) и `revshare-worker` (polling).
- В БД есть минимум:
  - 1 партнёр с одним приложением,
  - 1 партнёр с несколькими приложениями,
  - 1 партнёр без приложений (для негативного кейса).
- У каждого есть токен персональной ссылки.
- Бот-токен в `data/secrets.env` валиден, бот `@your_bot` доступен.
- У вас есть Telegram-аккаунт, который **не привязан** ни к одному из тестовых партнёров (свежий, чтобы `/start TOKEN` не сработал «случайно»).

## Что подготовить заранее

- `tests/conftest.py` нет, поэтому шаблоны/файлы готовим руками. Быстрее всего — через `pytest` в одну строку: `python -c "from revshare.report_template import build_report_template; open('/tmp/tmpl.xlsx','wb').write(build_report_template(partner_id=1))"`.
- Заполненный шаблон с 3 клиентами, разными Location ID, разными валютами.
- Шаблон с **одним** клиентом.
- Шаблон с **нулём** в поле оборота.
- Шаблон с **пустой** ячейкой оборота.
- «Сломанный» файл (`.xlsx` с битым архивом, либо `.txt` с расширением `.xlsx`).
- Шаблон с очищенной ячейкой `B3` (период).

## Ход сценария

### Шаг 1. Привязка чата

1. В Telegram откройте бота, нажмите **Start**.
2. Отправьте `/start <TOKEN_ПАРТНЁРА_С_ОДНИМ_ПРИЛОЖЕНИЕМ>`.
3. Бот должен ответить приветствием с названием партнёра.

**Ожидаемо:** `chat_id` привязался к партнёру. Проверить в `/admin/partners/{id}/edit` → вкладка «Telegram» — там виден handle.

**Истории:** P-09 (вспомогательно), привязка.

---

### Шаг 2. Запрос шаблона

1. Нажать кнопку **«Запросить шаблон»** (reply-клавиатура).
2. Должен прийти Excel-файл.

**Ожидаемо:** файл пригоден для заполнения, имя не содержит конкретного периода.

**Истории:** P-01.

**Альтернатива:** отправить `/template` — то же поведение.

---

### Шаг 3. Загрузка «хорошего» отчёта

1. Заполните шаблон с 3 клиентами.
2. На второй лист положите любой пример (он не должен попасть в разбор).
3. В `B3` укажите текущий месяц на русском, **но подписью к сообщению в Telegram напишите другой месяц** (например, файл — «Сентябрь 2026», подпись — «отчёт за август»).
4. Отправьте файл боту.

**Ожидаемо:**
- Бот показал сводку: партнёр, период (= B3, **не подпись**), приложение, число клиентов, оборот, сумма к выплате.
- Кнопки: «Подтвердить» / «Отменить» / (если приложений несколько) «Выбрать приложение».

**Истории:** P-02, P-03, P-09, P-13.

---

### Шаг 4. Подтверждение

1. Нажмите **«Подтвердить»**.
2. Бот должен ответить «Отчёт сдан».

**Ожидаемо:** в `/admin/partners/{id}/edit` появился отчёт со статусом «Партнёр сдал отчёт».

**Истории:** P-13, P-16 (идемпотентность подтверждения).

---

### Шаг 5. Защита от двойного подтверждения

1. Загрузите файл с другими значениями (2 клиента вместо 3).
2. **Дважды быстро** нажмите «Подтвердить» (в пределах ~1 секунды).

**Ожидаемо:** создана **одна** новая версия, не две. В истории видно одну запись с timestamp.

**Истории:** P-16.

---

### Шаг 6. Нулевая оплата

1. Заполните шаблон, в одной строке клиента поставьте оборот `0`.

**Ожидаемо:** бот показал сводку с этой строкой, никакой ошибки.

**Истории:** P-06 (положительный кейс).

---

### Шаг 7. Пустая сумма (отказ)

1. Заполните шаблон, в одной строке клиента оставьте ячейку оборота пустой.

**Ожидаемо:** бот отказал, **с указанием номера строки**. Новый черновик не создан.

**Истории:** P-05, P-06 (отрицательный кейс).

---

### Шаг 8. Один клиент

1. Отправьте файл с **одним** клиентом.

**Ожидаемо:** бот предложил подтвердить. Никакого «отчёт отклонён, потому что один клиент».

**Истории:** P-07.

---

### Шаг 9. Несколько приложений

1. Переключитесь на партнёра с **несколькими** приложениями (`/start TOKEN_2`).
2. Загрузите файл.

**Ожидаемо:** бот показал клавиатуру выбора приложения, **только свои** приложения. После выбора — сводка.

**Истории:** P-10, P-12.

---

### Шаг 10. Нет приложений

1. Переключитесь на партнёра **без** приложений (`/start TOKEN_3`).
2. Загрузите файл.

**Ожидаемо:** бот отказал, понятное сообщение «обратитесь к администратору». Ни черновик, ни отчёт.

**Истории:** P-11.

---

### Шаг 11. Битый период

1. Возьмите заполненный шаблон, очистите `B3`.
2. Отправьте боту.

**Ожидаемо:** бот ответил «исправьте файл и пришлите заново». Нового черновика нет.

**Истории:** P-04.

---

### Шаг 12. Битый файл

1. Переименуйте `template.xlsx` в `template.txt`, отправьте.
2. Повторите с реально битым `.xlsx` (обрезать первые 4 байта, например).

**Ожидаемо:** бот отказал, понятное сообщение. Никаких 5xx, никаких зависших черновиков.

**Истории:** P-05.

---

### Шаг 13. Исправленная версия

1. После шага 4 откройте `/admin/partners/{id}/edit` и **подтвердите** отчёт.
2. Отправьте **исправленный** файл за тот же период.
3. Подтвердите.

**Ожидаемо:**
- Появилась **новая версия** отчёта.
- Старое подтверждение сброшено — статус снова «Партнёр сдал отчёт», админу нужно подтвердить заново.

**Истории:** P-15.

---

### Шаг 14. Несколько приложений за один месяц

1. Партнёр с 2+ приложениями.
2. Сдайте отчёт за **один** месяц для приложения A (сумма X).
3. Сдайте отчёт за **тот же** месяц для приложения B (сумма Y).
4. Подтвердите оба.

**Ожидаемо:** в `/admin/partners` оба видны, суммы не перезаписаны.

**Истории:** P-17.

---

## Что записать в протокол

| Поле | Что писать |
|---|---|
| ID сценария | `bot-flow` |
| Дата и время | когда прогоняли |
| Проверил | кто именно |
| Ветка и коммит | `git rev-parse HEAD` |
| Среда | `127.0.0.1:43127`, версия `revshare-worker` |
| Состав | реальные или тестовые партнёры; был ли доступен Telegram |
| Ограничения | что не удалось проверить и почему |

В таблице результатов — отметка по каждой проверенной истории (P-01..P-17). Если что-то не работает — сразу писать шаги и фактический результат в поле «Ошибка или комментарий».

Шаблон: [`../../acceptance/run-template.md`](../../acceptance/run-template.md).
